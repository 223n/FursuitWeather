# イベント予報の定義（events.json）

トップページの地点の選び方にある「イベント」タブに表示するイベントの
一覧は、`public/events.json`で定義します。タブを選び、リストから
イベントを選んで「開催地の予報を表示」を押すと、開催地の予報が
表示されます。

開催地は**郵便番号**で指定します。座標は画面側が
`GET /api/geocode`（郵便番号→市区町村名→座標）で解決するため、
緯度経度を調べる必要はありません。

## 書き方

`public/events.json`の`events`配列にイベントを追加します。

```json
{
  "events": [
    {
      "name": "けもケット17",
      "place": "TRC東京流通センター",
      "zip": "143-0006",
      "startDate": "2026-09-20",
      "startTime": "12:00",
      "endTime": "17:00"
    },
    {
      "name": "Kemocon 19",
      "place": "御殿場高原　時之栖",
      "zip": "412-0033",
      "startDate": "2026-11-06",
      "endDate": "2026-11-08",
      "startTime": "15:00",
      "endTime": "21:00"
    }
  ]
}
```

| 項目 | 必須 | 内容 |
|------|------|------|
| `name` | 必須 | イベント名（空文字は不可。重複も不可）。**固定リンク（`?event=`）と判定バッジ（`/api/badge.svg?event=`）の照合キー**のため、告知掲載後に変更（表記修正・改名）すると掲載済みのバッジは404で壊れ、固定リンクは通常表示へフォールバックします |
| `place` | 必須 | 開催場所の表示名（会場名など。空文字は不可） |
| `zip` | 必須 | 開催地の郵便番号（`143-0006`または`1430006`） |
| `startDate` | 必須 | 開催初日（`YYYY-MM-DD`形式） |
| `endDate` | 任意 | 開催最終日（`YYYY-MM-DD`形式、省略時は`startDate`と同じ=単日開催） |
| `startTime` | 任意 | 開催初日の開始時刻（`HH:MM`形式） |
| `endTime` | 任意 | 開催最終日の終了時刻（`HH:MM`形式） |

`startTime`・`endTime`を書いておくと、**単日開催**のイベントで開催日の
予報を表示したときに、**活動プランナーへ開催時間が自動で設定されます**
（終了時刻は時間単位へ切り上げます。19:30終了なら20時まで）。

複数日開催（`endDate`が`startDate`と異なる）では時刻を自動設定しません。
`startTime`・`endTime`は開催期間全体の開始・終了時刻のため、その日ごとの
開催時間が定義から決まらないためです。0時・24時で補うと開催していない
夜間まで着用可能時間の合計に積み上がり、熱中症対策の目安が安全側から
外れてしまいます。プランナーの日付だけを合わせるので、時間帯は画面で
選んでください。

## 画面での動き

- イベントは**開催が近い順**に並びます
- **終了済みのイベントは自動的に表示されなくなります**
  （`endDate`、単日なら`startDate`が過ぎたもの。定義から消す必要は
  ありませんが、増えてきたら整理してください。ただし判定バッジ
  （`/api/badge.svg?event=イベント名`）を告知ページへ掲載している
  イベントは、定義を削除するとバッジも表示されなくなります。
  バッジの貼り付け例・表示確認（`?demo=1`）は[API仕様](api.md)の
  `GET /api/badge.svg`（公開サイトの`/about`にも掲載）を参照）
- 開催日（開催中なら今日、これからなら初日）が予報の範囲内
  （今日から3日間）に入っていれば、予報の表示後に**その日のタブへ
  自動で切り替わります**
- 開催日がまだ予報範囲外の場合は、開催地の予報（今日から3日間）を表示し、
  **表示中がいつの予報なのかと、開催日の予報ではないこと**を案内します
  （開催が近づいてから再度選ぶと開催日の予報が見られます）
- 地点ラベルには、郵便番号から解決された実際の地名を併記します
  （例: 「けもケット17（TRC東京流通センター・大田区（東京都）付近）」）。
  意図した場所と違う地名が出たときは郵便番号の誤りが疑われます
- 郵便番号から開催地を特定できなかった場合は、その旨を表示します
  （郵便番号の誤りが疑われます）
- 定義が空・読み込み失敗のときは、「イベント」タブのセレクトとボタンが
  無効のまま（その旨の表示）になります

## イベント固定リンク（?event=）

`https://fursuit-weather.223n.tech/?event=イベント名`のURLで開くと、
一覧の読み込み後にそのイベントが自動で選ばれ、開催地の予報表示と
プランナーへの開催時間の反映まで進みます。イベント名は`events.json`の
`name`と完全一致で照合します（URLでは`encodeURIComponent`で
エンコードしてください）。告知ページやSNSへ貼る固定リンクとして
使えます。トップページのイベントタブで対象を選んで
「固定リンクをコピー」を押すと、エンコード済みのURLをそのまま
コピーできます。一覧に無い名前（開催終了・改名後など）は、その旨を案内して
通常の初期表示（記憶した地点または既定都市）にフォールバックします。

## 郵便番号から地点が決まるまで

1. zipcloudで郵便番号を住所へ変換します（例: `531-0073` → 大阪府 大阪市北区）
2. 市区町村名で座標を検索します。上流の地名データは「大阪市北区」の
   ような複合名や接尾辞付きの名前を持たないことがあるため、
   **政令市の区→市、郡→町村、接尾辞なし**の順に候補を短くしながら
   探します（大阪市北区→大阪市→大阪、伊都郡高野町→高野町→高野、
   御殿場市→御殿場）
3. 同名の地名が他県にある場合は、郵便番号の都道府県と一致する候補を
   優先します

## 予報の地点の精度について

CIが検証するのは**形式だけ**です。郵便番号が正しい書式で別の場所を
指していても検出できないため、**イベントを追加したら一度画面から選んで、
地点ラベルに出る地名が意図どおりか目視で確認してください**。
マージ前に確かめたい場合は、
`https://fursuit-weather.223n.tech/api/geocode?q=郵便番号`
（例: `?q=143-0006`）をブラウザで開くと、その郵便番号がどの地名・
座標へ解決されるかをJSONで確認できます。

郵便番号は市区町村名を経由して座標へ変換されるため、解決される地点は
**会場そのものではなく市区町村の代表点**になることがあります。
市域の広い自治体（那賀町・高野町など）や、市街地から離れた会場
（中部空港島のAICHI SKY EXPOなど）では、会場付近の実際の気象と差が
出ることがあります（予報は約5kmメッシュ）。標高差は暑さ指数・低温判定に
直結するため、当日は現地の体感と併せてご判断ください。
会場ピンポイントで確認したい場合は、地点検索や現在地から表示してください。

## 反映のしかた

`public/events.json`を編集してmainへマージすると、自動デプロイで
本番へ反映されます。GitHubのWeb画面から直接編集してPRを作る方法が
簡単です。

第三者の主催者から掲載の希望を受け付ける窓口は、このリポジトリの
issue（またはevents.jsonへのPR）です。トップページのイベントタブにも
issueへの案内を掲載しています。受け付けたら本ドキュメントの書き方に
沿って追加し、マージ前に郵便番号の解決先を確認してください。

反映されたイベントは、トップページのイベントタブの一覧に加えて、
カレンダー取り込み用の`/api/events.ics`（iCalendar形式。
詳細は[API仕様](api.md)）にも同じ基準で載ります。取り込まれた予定は
自動では更新されないため、開催情報を変更したときは利用者へ
再取り込みを案内してください。

予定のUIDは**開催初日+イベント名**から決まるため、変更内容によって
再取り込みの結果が変わります。

- **日程変更（`startDate`の変更）**: UIDが変わるため、再取り込みすると
  旧日程の予定がカレンダーに残ったまま新日程が追加されます。
  **旧日程の予定の削除も併せて案内してください**
- **時刻・会場のみの変更**: UIDが変わらないため、既存UIDの取り込みを
  スキップするアプリ（Google Calendarのインポートなど）では反映されない
  ことがあります。その場合は旧予定を削除してから再取り込みしてもらいます

## 検証

形式の誤り（必須項目の欠落・郵便番号や日付の書式誤り・終了日が開始日
より前・イベント名の重複など）は`test/events.test.ts`がCIで検出します。
フロントエンドも必須項目や書式が不正な項目は黙って表示から除外するため、
1件の定義ミスで画面全体が壊れることはありませんが、「登録したのに
表示されない」を避けるためPRのCI結果を確認してください。
