# アクセシビリティ設計

本サービスが採用しているアクセシビリティ上の設計判断をまとめます。
安全に関わる情報を扱うため、色覚多様性への対応とスクリーンリーダー対応を
機能要件として扱っています。

## 色覚多様性への対応

- カラーユニバーサルデザイン（CUD）推奨色をベースにしたパレットを
  使用します（`public/style.css`の`:root`変数）
- 判定の段階は色だけに依存せず、記号（◎○△✕・禁止マーク）と文字を
  必ず併記します
- 低温側の判定には温度計アイコンを付け、暑熱側と形で区別します
- 文字と背景のコントラストはWCAG AAを満たすよう、薄色背景+濃色文字の
  組み合わせで設計しています

### 注意文の共通枠（`.notice-panel`）

安全に関わる注意文は、ページをまたいで同じ見た目にそろえます。
注意レベルの配色（`--level-1-accent`の枠+`--level-1-surface`の地色）で
囲み、色だけに頼らせないよう左上（見出しまたは本文の先頭）に△!の
アイコンを置きます。見出しのない注意文には`sr-only`の「注意: 」を
添えて、読み上げでも役割が分かるようにします。

| 場所 | 対象 |
|------|------|
| index.html | 活動時の注意（`#notices-section`）・この予報についての注意文 |
| about.html | 利用上の注意・免責事項（`#disclaimer`） |
| emergency.html | やってはいけないこと・医療上の助言に代わらない旨の免責 |

熱中症警戒アラート相当の表示（`.alert-notice`）だけは警戒レベルとして
`--level-3-*`（赤系）のままにし、注意より上位であることを色でも
区別します。E2E（`e2e/app.spec.mjs`）が枠の色・太さとアイコンの位置を
ページ横断で検証します。

## アイコンの自前配信

アイコンはFont Awesome FreeのSVGをスプライト（`index.html`内）または
インラインで自前配信します。絵文字やWebフォントと違い、OS・ブラウザに
よらず同一の見た目で表示されます。装飾アイコンには`aria-hidden="true"`を
付け、読み上げ対象から除外します。

## スクリーンリーダー対応

- 読み込み完了時に、その日の要点（地点・天気・判定・活動時間帯）を
  `#sr-announce`（`aria-live`）で文章として通知します
- エラーは`role="alert"`の専用領域に書き、即時に読み上げさせます
  （通常メッセージは`role="status"`のpolite領域）
- 表の時刻列・先頭列は`th scope="row"`にし、セルを読み進めるときに
  対応する見出しが読まれるようにします
- 範囲記号「〜」は読み上げが環境依存のため、視覚は「〜」のまま
  読み上げは「から」になるよう分離しています
- 読み上げサマリー（`#sr-announce`）内の時刻は「09:00」ではなく
  「9時」形式にします（時間別テーブルの行見出しは視覚は「09:00」のまま、
  読みを`aria-label`で「9時」形式に補います）
- 装飾記号（開閉矢印・パンくずの区切りなど）は読み上げから除外します
- 日別カードはカード全体をボタンにせず、見出し内のボタンが選択と
  `aria-pressed`を担います（ボタン内に見出し・リストを入れると
  読み上げが平坦化されるため）。ボタンの目的はsr-onlyの文で補います
- 時間別テーブルはsr-onlyの`caption`で全列を列挙し、表の全体像を
  先に把握できるようにします（列の実態との同期はテストが検証）
- WBGTの数式は`aria-hidden`にし、代わりに読み下し文を
  スクリーンリーダー専用で用意しています
- 地点セレクトのchangeイベントはデバウンスし、矢印キーでの探索中に
  読み上げ通知があふれないようにします

### 読みの補正（誤読対策）

日本語の音声合成が誤読する・読みが環境依存になる表記は、視覚の表記を
変えずに読み上げだけを分離します（範囲記号「〜」を「から」と読ませる
方針の一般化）。

- **「着ぐるみ」→「きぐるみ」**: 多くの音声合成が「ちゃくぐるみ」と
  誤読するため、静的HTMLの可視テキストは`aria-hidden`の「着」+
  `sr-only`の「き」で読みを分離し、JSの動的な可視文言は`yomiText`
  （`public/app.js`。`display.js`にも複製部品あり）で同じ分離を
  行います。読み上げが主用途の文字列（`#sr-announce`のサマリー・
  バッジSVGの`aria-label`/`title`）は直接「きぐるみ」とかなで書き、
  同じ文を書き文字として使うコピー経路だけ漢字へ戻します
- **日付の曜日「（水）」→「（水曜日）」**: 括弧内の単漢字は訓読み
  （みず・ひ・つち…）になるため、読み上げには曜日名を渡します。
  対応は`yomiText`と同じ経路（`YOMI_PATTERN`が「着ぐるみ」と曜日の
  両方を拾う。app.jsとdisplay.jsの複製はhtmlSyncテストが同期検証）で、
  `setStatus`のライブ領域もこの関数を通します。マークアップを持てない
  場所は文字列側で書き下します（`option`要素は`formatDateSpoken`・
  `yomiSpokenText`、`#sr-announce`のサマリーは`announceSummary`が変換）。
  会場表示モードの「8/19（水）」は掲示の幅を保つため視覚は短いまま、
  読みだけ「8月19日（水曜日）」に分離します
- **記号・単位**: 「→」は読点、「#7119」は「シャープ7119」、「m/s」は
  「メートル毎秒」へ読みを分離します。しきい値の区切りには
  「スラッシュ」と読まれる「/」「／」を使わず「・」を使います。
  欠測の「-」は「予報なし」「場所の記録なし」などの語に読みを分けます
- **範囲・時刻**: JSがtextContentで書く文（ライブ領域・option要素）は
  マークアップで読みを分離できないため、「〜」でなく「から」と
  書きます。時間別テーブルの行見出し「09:00」は`aria-label`で
  「9時」と読ませます（日の入り注記付きの行も同様）
- **対応できない場所**: `<title>`・`site.webmanifest`・OGPメタ・
  共有ペイロード・コード例（`pre`内）はマークアップでの読み分離を
  持てないため表記のままです（誤読は残りますが表記の一貫性を優先）
- `.sr-only`には`user-select: none`を付け、範囲選択のコピーへ
  読み上げ用テキスト（「から」「き」など）が混入しないようにしています

## 動的UIの設計（地点検索・実測WBGTツール）

後から追加した対話UIでも、次の設計を守っています。

- **地点検索の候補一覧**: 候補は見出しラベルと`aria-labelledby`で
  関連付けたリストに表示し、件数と操作方法（「検索欄の下の一覧から
  選択してください」）をpoliteなステータス領域で通知します。
  候補が1件だけのときは選択操作を求めず自動で予報を表示します
- **実測WBGTツール**（トップページの「実測WBGT」タブ）: 判定結果は`role="status"`の
  ライブ領域へ書き込んで自動で読み上げさせます。結果領域は高さを
  事前確保し（CLS対策）、バッジ記号は`aria-hidden`にして読み上げは
  ラベルのみにします。入力欄は`label`と`inputmode="decimal"`で
  入力を支援します
- **イベント選択**: 行は静的に配置し、セレクトの幅を固定して選択肢の
  読み込みによるシフトを防ぎます。定義が空・読み込み失敗のときは
  その旨を選択肢に表示して無効化し、表示結果（開催日のタブ切り替え・
  予報範囲外の案内）はpoliteなステータス領域で通知します。選択肢内の
  期間表記「〜」は読み上げが環境依存ですが、`option`要素は装飾を
  持てないため許容しています（開始・終了の日付自体は読み上げられます）

## キーボード操作とフォーカス

- 各ページ（トップ・about・emergency・404）の先頭に「本文へスキップ」
  リンクを置き、フォーカス時のみ表示します（会場表示モード
  （display.html）は「トップページへ戻る」リンクが同じ位置を担います）
- タッチ端末（`pointer: coarse`）ではボタン・セレクト・入力欄・
  折りたたみ見出し・aboutのパンくずリンク・応急対応ページへの安全導線
  （タイマー内・判定カード内・注意欄）のタップ領域を約44px
  （2.75rem）確保します（WCAG 2.5.8目安）。マウス環境は従来の密度を
  保つ判断です
- 主要コンテンツの切り替えはWAI-ARIAタブパターンで実装します
  （`role="tablist"`／`tab`／`tabpanel`、矢印キーで隣のタブへ移動して
  自動選択、Home/Endで先頭・末尾）。時間別の3タブ（今日/明日/明後日）は
  同じパネルを共有し、`aria-labelledby`を選択中のタブへ付け替えます。
  取得日数が足りない日付タブは非表示にします
- タブの見た目はノートのタックインデックス風にし、**選択状態を色だけに
  依存させません**。選択中のタブは下辺の線を消して内容と地続きにつながり、
  未選択のタブは地色を敷いて奥に見せます（形の違い）。加えて太字にします。
  タブの縁はカード地色・ページ地色・未選択タブ地色のいずれに対しても
  3:1以上（WCAG 2.1 SC 1.4.11）を確保しています
- 地点の選び方（主な都市／イベント／検索・現在地／お気に入り）も同じ
  タブパターンで切り替えます。2つのタブバーはそれぞれ`aria-label`で
  役割を示し、実装は共通の`createTabs`（`public/app.js`）を使います。
  キーボード移動の起点はフォーカス中のタブです
- 表示中の地点に対する操作（予報を更新・共有・お気に入りに追加）は
  選ぶ操作と分けて地点ラベルの下にまとめ、タブに関係なく常に押せます。
  さらに使う場面が限られる操作（会場表示・印刷・画像で共有・共有URLの設定）は
  折りたたみ（`.location-more`）へ入れ、操作エリアの末尾に置きます
- 当日の運用ツール（見守りモード・コンディションチェック・着用記録・
  当日ボード）は予報タブの外（`.day-tools`）に置き、どのタブを見ていても
  到達できるようにしています
- フォーカスリングは背景とのコントラスト3:1以上（WCAG 2.1
  SC 1.4.11）を満たす濃色（`#A66E00`）にしています
- すべての操作はボタン・リンク・フォーム要素で実装し、キーボードのみで
  完結します（検索欄のEnterは検索を実行）

## 会場表示モード（display.html）の設計判断

イベント会場のモニターへ掲示する自動表示ページは、自動で動き続けるUIの
ため次の判断をしています。

- **自動送りの制御（WCAG 2.2.2）**: 可視の「一時停止」ボタンで止められ、
  再開の操作まで停止が維持されます。スライド領域内にキーボードフォーカスが
  ある間も自動送りを止めます
- **読み上げの抑制**: スライドは15〜20秒ごとに切り替わるため`aria-live`を
  付けません（付けると読み上げが切り替えのたびに走り使い物にならない）。
  非表示スライドは`hidden`で、支援技術からは常に1枚だけ見えます。
  警告帯は内容が変わらない限りDOMを差し替えず、読み上げ位置を保ちます
- **進行表示**: 進行ドットは装飾（`aria-hidden`）とし、現在位置は
  塗り+サイズ差（色のみに依存しない）で示し、実質のインジケーターは
  隣の可視のスライド名文字が担います
- **警戒表示の形状差**: 熱中症警戒アラート基準相当の帯は、注意（黄系）との
  区別を色に加えて二重枠の形状差でも示します
- **?theme=light**: 会場PCのOS設定がダークでも明色で掲示できます
  （style.cssのダーク変数を`:root:not([data-theme='light'])`でガード）
- **全国セルの組み方**: 横長画面では1セルを「都市名・天気」「最高気温・判定」の
  2列2行に組みます。縦積み4行のままだと、9都市以上（3行のグリッド）で
  1行の高さが足りず、`overflow: hidden`によって都市名の上と判定バッジの下が
  黙って切れていました（1024x640〜1920x1080で再現）。2行目の高さは
  `grid-template-rows: minmax(0, 1fr) auto`で先に確保し、追加都市の長い名前が
  折り返しても、安全情報である判定を押し出さないようにしています。
  長い名前は2行で打ち切って省略記号を出し、読み上げ用に全文はDOMへ残します
  （E2E（`e2e/display.spec.mjs`）が横長の主要サイズと長い都市名で検証）
- **縦画面の全国セルの間引き**: 縦画面は1セルが低く、都市の追加・警告帯の本数・
  画面の小ささが重なると4要素が2行に収まりません。セルの実寸をコンテナクエリで
  見て、収まらないときは天気・最高気温を落とし「都市名＋判定」の1行にします。
  さらに低いときは文字を縮めますが、0.7remを下限にして読めない大きさにはしません
  （下限を下回る場合は表示する都市を減らして運用します）。この段階では記号の
  拡大率も1.35emから1.1emへ下げますが、文字より大きい関係は保ちます。
  落とす順序は「安全情報である判定を最後まで残す」を基準にしており、
  記号+文字の併記とCUD配色そのものは変えていません。
  コンテナクエリ非対応の古い端末では従来どおりの表示に戻ります

## 横スクロールの案内

時間別予報テーブルは列数が多く、スマホでは安全上重要な「屋外判定」
「連続活動目安」の列が初期表示の画面外に隠れます。横にスクロール
できることに気付けない利用者のために、表の前へ「表を横にずらすと
続きが見られます」という文字の案内（`.table-scroll-hint`）を置きます。
表が収まる広い画面ではCSSで非表示にします。

## レイアウトシフト（CLS）対策

- 地点セレクトの選択肢・注意事項・判定凡例は、初期描画から高さを
  確保するため`index.html`に静的に記載します（注意事項・凡例は
  `src/constants.ts`と、地点セレクトは`app.js`のCITIES配列と、
  それぞれ`test/htmlSync.test.ts`が同期を検証）
- 初期表示の位置に影響する折りたたみ（`.controls`内の`details`）の開閉を、
  `defer`の`app.js`から後付けで変えないこと。描画済みのタブ・判定カードが
  押し下げられ、触りに行った瞬間に位置がずれます（実測でCLS 0.06・ずれ幅137px）。
  開いた状態で見せたい要素はHTMLに`open`を書き、閉じたい条件があるなら
  HTMLのパース中に実行されるスクリプトで確定させます。
  画面下端の当日ボード（`.board-section`）は初期ビューポートの外にあるため対象外で、
  登録者がいる状態の再読み込みでは`app.js`が意図的に開きます（見守りを途切れさせないため）
- 読み込み中はスケルトンで領域を確保し、データ到着時に置き換えます
- ステータス領域は通常メッセージとエラーをgridで同じ位置に重ね、
  出現・消滅で高さが変わらないようにします
- 検索候補の一覧は利用者の操作起点で現れるため、CLS対策の対象外とする
  判断をしています（突然のシフトではなく操作への応答のため）
- スケルトンの点滅アニメーションは`prefers-reduced-motion`設定で
  無効化し、動きに敏感な利用者に配慮します

## 検証方法

文言・凡例の同期はvitest（`test/htmlSync.test.ts`）が機械検証します。
次の2つはリリース時に手動で測定し、トップ・aboutの両ページで
axe-core違反0件・CLS 0.000を確認しています（依存保守コストを避けるため
リポジトリの依存には含めていません）。

- axe-core監査: `npm run dev`で起動したページにaxe-coreスクリプトを
  注入して`axe.run()`を実行する（ブラウザ開発者ツールまたはPlaywright経由）
- CLS測定: Playwrightで`PerformanceObserver`（`layout-shift`）を購読し、
  読み込み完了までのシフト量を合算する
